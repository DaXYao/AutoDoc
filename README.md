# 项目背景与目标

## 1. 项目概述

- **项目名称（暂定）**：AutoDoc
- **项目定位**：一个面向开发者的**代码自动文档工具**，在完成项目代码撰写后，为每个代码文件自动生成结构化、可交互的文档，并通过 Web 页面查看、搜索、批注和维护。
- **核心形态**：本地运行的开发工具（CLI + 本地 Web 服务），最终目标是做成一个成熟的、可插件化扩展的开源项目。

---

## 2. 项目背景

### 2.1 痛点

1. 开发者完成代码后，往往没有时间和动力编写配套文档，文档与代码脱节、过时快。
2. 现有工具（如 Doxygen、JSDoc、Sphinx 等）以「注释提取 + 静态生成」为主，存在以下不足：
   - 无法区分「业务接口 / 实现接口 / 辅助工具」三种角色，文档层级不清晰；
   - 缺少「用户批注」机制，无法让开发者在文档上随时补充人工经验；
   - 缺少函数级「最近变更」追踪，读者难以判断文档新鲜度；
   - 缺少「调用关系」的自动整理与分类展示；
   - 大多是只读静态页面，不支持交互式编辑。

### 2.2 本项目要解决的问题

在自动生成文档的基础上，提供：
- **三分类方法整理**：业务接口、实现接口、辅助/工具函数；
- **可随时增改的用户批注**（带日期）；
- **代码注释 + 代码块的成对展示（注释块）**；
- **内部调用关系按三类聚合展示**；
- **函数级最近三次变更记录**；
- **简洁可折叠的 Web 交互界面**。

---

## 3. 项目目标

### 3.1 总体目标

开发者写完代码后，运行工具即可在浏览器中查看每个文件的结构化文档，并可持续维护批注；文档随代码变更自动更新，帮助团队快速理解代码内部细节。

### 3.2 具体目标

1. **自动文档生成**：每个源代码文件对应一份文档。
2. **三分类整理**：每个方法/接口自动归类为「业务接口」「实现接口」「辅助/工具函数」。
3. **用途说明**：每个方法自动生成或提取用途描述。
4. **用户批注**：用户可随时添加、修改、删除批注，批注带作者和日期。
5. **注释块**：提取方法内部的「注释 + 紧随代码块」，成对展示，便于理解内部细节。
6. **内部调用关系**：展示每个方法内部调用了哪些其他函数，并按三分类分组。
7. **最近三次变更**：记录并展示每个函数的最近三次变更（新增/修改/删除/重命名）。
8. **Web 交互界面**：每个文件一个页面，从上到下为「文件名 → 业务接口 → 实现接口 → 辅助/工具函数」；支持名称搜索跳转；所有内容可折叠展开，界面保持简洁。
9. **可配置性**：分类规则、默认展开策略等均可配置。
10. **可扩展性**：插件化架构，支持逐步接入更多编程语言与输出格式。

## 4. 核心概念定义

### 4.1 三类方法

| 类别 | 定义 | 典型示例 |
|---|---|---|
| **业务接口（business）** | 对外暴露的入口，内部一般会调用实现接口 | HTTP Handler、Controller、RPC 服务、公共库公开 API、CLI 命令 |
| **实现接口（implementation）** | 业务接口背后的具体逻辑，通常被业务接口调用 | Service 实现类、内部核心流程函数 |
| **辅助/工具函数（utility）** | 无业务状态、可复用的通用函数 | 字符串处理、日期格式化、参数校验、加解密工具 |

> 三类是「角色标签」而非语言概念，分类规则必须可配置，不同项目可有不同约定。

### 4.2 用户批注（Annotation）

- 用户**手动添加**的信息，附加在某个函数、文件或模块上；
- 必须包含：内容、作者、创建日期、最后修改日期；
- 可随时添加、修改、删除；
- 与代码自动生成的内容明确区分。

### 4.3 注释块（Code Block）

- 指方法体内部的「注释 + 紧随其后的代码块」的组合；
- 展示时注释与代码成对出现，帮助快速理解局部实现细节；
- 例：`// 校验输入参数` 后面紧跟的 `if (...) { ... }` 校验代码，整体作为一个注释块。

### 4.4 最近三次变更

- 针对每个函数，记录其最近三次变更；
- 变更类型：新增（added）、修改（modified）、删除（deleted）、重命名（renamed）；
- 每条记录包含：日期、变更类型、简要说明（如参数变化、调用了新函数等）。

### 4.5 内部调用关系

- 方法体内对其他函数的调用；
- 展示时按被调用函数的三分类（业务/实现/辅助）分组；
- 无法解析的调用（外部库、跨文件未解析等）归为「外部/未解析」，不强行猜测。

## 5. 功能需求

### 5.1 文档生成

1. 扫描项目源代码文件，识别语言。
2. 解析出类、函数/方法、参数、返回值、可见性、装饰器/注解、文档注释（docstring/JSDoc/Javadoc）、函数体内调用点。
3. 为每个函数生成稳定 ID（相对路径 + 类名 + 方法名 + 参数签名哈希）。
4. 为每个函数计算指纹（函数体 AST 结构哈希），用于变更检测。
5. 为每个文件生成一份文档。

### 5.2 方法分类

1. 采用多层分类策略：
   - 第一层：硬规则（装饰器/注解、目录约定、命名约定、可见性）；
   - 第二层：用户配置规则（JSON/YAML 配置文件）；
   - 第三层（可选，后期）：LLM 辅助分类与用途说明生成。
2. 分类置信度低的方法标记为「待确认」，由用户手动指定。

### 5.3 用途说明

1. 优先提取现有文档注释；
2. 无注释时，根据签名和上下文生成简单模板化描述；
3. 用户可通过批注补充或覆盖。

### 5.4 批注系统

1. 支持对函数、文件、模块三个层级添加批注；
2. 添加方式：Web 界面表单（主）、代码内特殊标签（如 `@anno`，辅助）、CLI（辅助）；
3. 批注内容支持 Markdown；
4. 批注记录创建日期和最后修改日期，显示作者。

### 5.5 注释块

1. 解析时，将方法体内部的注释节点与紧随其后的语句/代码块配对；
2. 多行连续注释合并为一条；
3. 注释块包含：注释文本、代码文本、起止行号、所属函数 ID；
4. Web 界面上注释块可独立折叠展开；
5. **已确认的增强项**：注释块支持「跳转到源码对应行」的能力（通过编辑器链接或 IDE 插件）。

### 5.6 内部调用关系

1. 解析函数体内调用点，映射到目标函数 ID；
2. 在文档中按目标函数的三分类分组展示；
3. 解析不到的调用归为「外部/未解析」。

### 5.7 变更追踪

1. 优先基于 Git 历史（读取 commit log）做函数级变更检测；
2. 无 Git 时，使用本地指纹快照对比；
3. 只展示每个函数最近三次变更，更早记录归档（保留但不展示）。

### 5.8 Web 界面

1. **运行模式一（交互模式）**：`serve` 命令启动本地 Web 服务，浏览器访问；支持批注增改。
2. **运行模式二（导出模式）**：`export` 命令生成只读静态站点，批注内嵌，用于分享或归档。
3. **页面布局**：每个文件一个页面，主内容区从上到下依次为：
   - 文件名（含文件说明、文件级变更，可折叠）；
   - 业务接口区块；
   - 实现接口区块；
   - 辅助/工具函数区块。
4. **方法展示**：默认只显示「方法名 + 一句话用途」，展开后显示完整信息（签名、用途、批注、内部调用、注释块、最近变更）。
5. **搜索**：顶部搜索框，按方法名模糊搜索，结果跨文件展示；选中后跳转到对应文件页面并自动展开定位到该方法，高亮 2 秒。
6. **批注编辑**：方法卡片和文件区块内提供「添加批注 / 编辑 / 删除」入口。
7. **折叠策略**：
   - 默认：文件名展开，三个分类区块折叠（只显示标题 + 数量）；
   - 方法卡片内的「内部调用」「注释块」「最近变更」再折叠一层；
   - 用户展开/收起状态保存到浏览器本地（localStorage），下次保持。
8. **默认展开策略可配置**（已确认的约定项）：如 `业务接口默认展开`、`辅助函数默认收起` 等均通过配置控制，不硬编码。

### 5.9 可配置项

- 分类规则（目录模式、装饰器/注解列表、命名约定）；
- 默认展开/收起策略；
- 批注存储方式（SQLite 或侧车文件）；
- 输出目录、包含/排除的文件范围。

## 6. 技术方案（已确定）

### 6.1 总体架构

```
浏览器（SPA）
    │ REST API
本地服务（serve）
    │
核心引擎（解析 → 抽取 → 分类 → 建图 → 注释块 → 变更 → 生成）
    │
元数据存储（SQLite / 侧车文件）
```

### 6.2 技术栈

| 层 | 技术选型 | 说明 |
|---|---|---|
| 核心语言 | TypeScript（Node 20+，ESM） | 全栈统一，前后端共享类型定义 |
| 代码解析 | tree-sitter + 各语言 grammar | 多语言统一 API、容错性强、增量解析 |
| 后端服务 | Fastify | 快、TS 友好 |
| 前端框架 | **Vue 3 + Vite + TypeScript**（默认方案；如团队更熟悉 React 可整体替换为 React 18，不影响其他层） | SPA |
| 样式 | Tailwind CSS | 快速搭建简洁界面 |
| 组件库 | Naive UI（Vue 系） | 折叠面板、表单、弹窗等现成组件 |
| 路由 | Vue Router | `/files/:fileId` |
| 搜索 | Fuse.js（前端模糊搜索） | 大型项目后期可下沉为服务端 SQLite FTS5 |
| 代码高亮 | Shiki | 注释块代码着色，接近 IDE 效果 |
| Markdown 渲染 | markdown-it | 批注内容支持 Markdown |
| 元数据存储 | SQLite（better-sqlite3）+ 可选侧车 JSON/YAML | 通过存储适配器抽象 |
| Git 集成 | simple-git | 变更追踪 |
| 配置 | JSON Schema 校验 + cosmiconfig | 配置文件发现与校验 |
| CLI | commander + chokidar | 命令与文件监听 |
| 测试 | Vitest | 单元测试 + 各语言 fixture 仓库 |
| 发布 | pnpm monorepo | 核心库 / CLI / 前端 / LSP 分包 |

### 6.3 关键数据模型（要点）

- **FunctionDoc**：函数/方法文档实体，含稳定 ID、签名、分类（business/implementation/utility）、用途、指纹、批注列表、调用列表、注释块列表、最近三次变更。
- **Annotation**：批注实体，含目标 ID、作者、内容、创建时间、修改时间。
- **CodeBlock**：注释块实体，含注释文本、代码文本、起止行号、所属函数 ID。
- **CallEdge**：调用边，含调用方 ID、被调用方 ID、被调用方分类。
- **ChangeRecord**：变更记录，含日期、变更类型、简要说明。

> 核心设计原则：批注与变更历史通过「稳定 ID + 指纹」关联，而非文件名，以应对函数重命名和文件移动。

## 7. 非功能性需求

1. **可扩展性**：语言解析器、分类规则、输出格式、存储后端均采用插件/适配器模式。
2. **性能**：中等规模项目（数千文件）下，单次全量生成应在可接受时间内完成；支持 `--watch` 增量更新（只重算变更文件）。
3. **容错性**：代码不完整、解析失败时降级处理，不中断整体流程。
4. **可维护性**：前后端共享 TypeScript 类型；核心逻辑与 UI 解耦。
5. **用户体验**：界面简洁，默认折叠细节，操作路径短。

## 8. 开发阶段建议

| 阶段 | 内容 | 产出 |
|---|---|---|
| Phase 1（MVP） | 核心引擎 + 三分类 + 调用图（文件内/类内）+ 注释块提取 + Web 界面（文件页、三区块、搜索跳转、批注增改、折叠）+ `serve` 模式 | 可运行的本地交互工具 |
| Phase 2 | 稳定 ID + 变更追踪（最近三次）+ `export` 静态导出 + `--watch` 增量更新 + 单元测试 | 稳定可用的工具 |
| Phase 3 | 插件体系正式化 + 注释块跳转源码 + CI 集成 + 文档站点聚合 + 多语言扩展 | 成熟项目形态 |
| Phase 4（远期） | LLM 辅助分类与用途生成（可选、可缓存）+ 跨文件调用图 + 完整变更历史 + 团队协作 | 进阶能力 |

## 9. 已确认的约定与决策

1. 注释块支持**独立查看**，并预留「跳转到源码对应行」能力。
2. **默认展开策略可配置**，不硬编码；用户展开状态本地持久化。
3. 界面采用单列纵向布局：文件名 → 业务接口 → 实现接口 → 辅助/工具函数。
4. 批注与自动生成内容明确分离展示。
5. 变更历史只展示最近三次，更早记录归档。
6. 前端框架默认 Vue 3，如更换为 React 需整体替换前端层，其余层不变。

---

## 10. 暂不包含（Out of Scope，第一阶段）

- 多用户云端协作与远程批注同步；
- 完整（超过三次）的变更历史展示；
- 跨文件/跨模块的完整调用图（仅做文件内/类内解析）；
- LLM 自动生成用途说明（作为远期可选能力）。
